# 수집 스택 (과제 1)

MQTT(ChirpStack) → 수집기 → InfluxDB 2.7. 모두 Docker로 돌고, 보드 재부팅이나 장애 후 자동으로 다시 시작된다.

| 항목 | 값 |
|---|---|
| 위치 | `/srv/team/ingest` |
| InfluxDB | `http://localhost:8086` (보드 안에서만 열림), org `team2`, bucket `sensors` |
| 비밀값 | `.env` (team 그룹만 읽기 가능, 공유·커밋 금지) |

## 버킷

| 버킷 | 내용 | 기간 | 채우는 방법 |
|---|---|---|---|
| `sensors` | 우리 수집기가 MQTT로 받은 실시간 원본 | 2026-10-20 10:21~ | collector (상시) |
| `history` | 운영진 InfluxDB(iot-bucket)의 과거 원본 | 2025-08-08 ~ 2026-10-20 15:06 | `/srv/team/tools/export_history.py`(Mac, 내부 LAN) → Parquet → `load_history.py` |

두 버킷은 겹치는 구간(10/20 10:21~15:06)이 있다. 정제 코드에서 합칠 때 기준 시각을 정해 한쪽만 쓴다. 과거 원본 파일은 `/srv/team/data/raw/influx_history/`에 따로 있다.

## 저장 구조

| measurement | tags | fields |
|---|---|---|
| `env` | location, point, spot, dev_eui, device, model | 센서 `object`의 숫자 값 전부(co2, temperature, humidity, pressure, tvoc, battery …), 모두 float |
| `uplink` | location, point, spot, dev_eui, device, model | fcnt, rssi, snr, dr (결측 원인 분석용) |
| `collector` | name | received, written, duplicate, write_error, pending, mqtt_connected (1분마다) |

- `history` 버킷도 `env`(센서값), `uplink`(rssi, snr) 구조가 같다. 태그는 location, point, spot, dev_eui(+ gateway_id)이고, device, model 태그는 없다.
- **센서를 이어 붙이는 키는 `dev_eui`**다. point, spot, dev_eui 태그는 2026-10-20 15:16부터 수집기에도 붙는다. 그 전 `sensors` 데이터는 device 태그로 구분한다.
- 2025년 초기 데이터 일부는 dev_eui가 없다(약 5.6%). 이 경우 location + point로 센서를 구분한다.

- 시각: 메시지의 `time`(게이트웨이 수신 시각, UTC). 분석할 때 KST로 변환한다.
- 중복: `deduplicationId`로 제거한다.

## 자주 쓰는 명령 (보드에서)

```bash
cd /srv/team/ingest
docker compose ps                               # 상태
docker compose logs -f --tail 50 collector      # 수집기 로그
docker compose exec collector python coverage.py 24          # 최근 24시간 커버율
docker compose exec collector python coverage.py 24 co2      # 항목 지정
docker compose restart collector                # config.yaml 수정 후 반영
docker compose up -d --build                    # 코드 수정 후 반영
```

## Mac에서 InfluxDB 웹 UI 보기

```bash
ssh -N -L 8086:localhost:8086 <USER>@<JETSON_HOST>
```
이 명령을 켜 둔 채로 브라우저에서 http://localhost:8086 을 연다. 계정은 `admin`, 비밀번호는 보드에서 `grep INFLUX_ADMIN_PASSWORD /srv/team/ingest/.env`로 확인한다.
Python에서도 `INFLUX_URL=http://localhost:8086`과 `.env`의 `INFLUX_TOKEN`으로 같은 터널을 통해 접속할 수 있다.

## 형식 변경 대응

`collector/config.yaml`의 `sources`만 고친다. 새 토픽이나 새 메시지 형식은 source를 추가하고, 필드 이름 변경은 `rename`, 제외는 `exclude`로 처리한다. 수정한 뒤 `docker compose restart collector`로 반영한다.
